# 历史身份一致性修正接口需求草案

当前插件只提供历史只读预览。本文件用于后续向 MoviePilot 上游提出接口需求，尚未提交 Issue 或 PR。

## 问题

同一下载的下载历史和整理历史可能保存豆瓣/Bangumi主身份，而 Emby 删除事件使用 TMDB 身份。只更新一类历史会留下不一致；插件不应绕开公开 Oper/Chain 直接修改宿主 ORM、Session 或 SQL。

## 建议的宿主能力

提供一个公开 Chain/应用服务，在同一事务中修正一个下载关联的两类历史身份。输入包括下载历史ID、任务hash、原身份、目标TMDB身份、预览时的关联整理记录ID及用于乐观并发校验的原值。不得接受调用方提供的SQL或任意更新字段。

宿主执行前重新核验目标身份与媒体类型、季集一致性、任务和历史归属及关联集合未变更；并与下载/整理任务互斥。事务只更新已确认的身份字段，保留历史ID、路径、时间、文件状态、选集及任务关联。任一记录不符合预期或写入失败时，整组回滚。

返回明确的成功、过期预览、身份不确定、并发任务或不支持等结果，并记录原/目标身份及处理记录ID以供审计。相同请求重复执行应返回已完成或无变更，不触发文件整理、下载、Emby扫描或删除。

## 插件接入门槛

接口正式提供并验证 SQLite/PostgreSQL、回滚、并发与幂等行为后，插件才能显示确认更新入口。旧宿主继续提供只读预览，并解释未开放写入的原因。
